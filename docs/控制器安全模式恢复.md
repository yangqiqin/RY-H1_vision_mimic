# 控制器安全模式 / “程序节点未找到” 现场恢复指南

## 现象
示教器提示：**程序节点未找到 / 程序运行出现问题 / 处于安全模式**，机械臂无法启动或拒绝运动。

## 这是什么
Aubo 控制器以"程序(RTM 运行节点)"管理实时控制。伺服(servoJoint)等实时接口依赖该程序节点；
若之前程序异常退出、伺服中途被打断或触发了安全保护，控制器会进入安全/保护模式并报
"程序节点未找到"。**这不是 Python 工程问题，是控制器侧状态**，需现场恢复。

## 恢复步骤（按顺序执行）
1. **确认不是保护性停止(PSTOP)**：示教器查看"安全"页；若报 Protective Stop，先排查原因
   （速度/区域/扭矩），按示教器**使能键**确认安全状态是否可清除。
2. **示教器复位**：点示教器【停止】→【复位】；安全模式若能清除则先清除。
3. **彻底重启控制柜**：关控制柜电源，等 10~20 秒，重新上电，等机器人自检完成。
   （多数"程序节点未找到/安全模式"在断电重启后自动恢复。）
4. **上电+启动程序**（二选一）：
   - 示教器：新建/打开一个**空白项目**并启动，确认示教器显示"运行中/空闲"正常；
   - 或 SDK：运行 `python tools/recover_arm.py`（连接→打印模式→上电+启动→确认 Running）。
5. 确认状态正常后再用 GUI 连接测试（先不要勾选伺服模式）。

## 若断电重启仍"程序节点未找到"
- 在示教器手动新建一个简单程序(可只含等待)并运行一次，让控制器重建运行节点；
- 检查控制柜固件版本并咨询遨博技术支持（可能与固件/RTM 有关）。

## 预防（本工程侧）
- **伺服实时模式为实验功能**：它需要稳定的 RTM 程序环境且与控制器安全联动紧密，
  实验出现异常可能把控制器带进安全模式。恢复控制器后，**默认不要再勾选"伺服实时模式"**，
  先用"常规 move 模式"跑稳定；
- 开始跟随时代码会检查机器人是否 Running；若处于安全/非 Running 会拒绝启动；
- 一旦示教器出现保护/安全提示：停止本工程所有运动命令，按上面步骤恢复。

## 快速状态诊断（SDK）
```bash
python tools/recover_arm.py --status     # 只打印 模式/安全模式/是否运行，不动臂
python tools/recover_arm.py              # 上电+启动并确认 Running（机器人会先上电后断电一次）
```
