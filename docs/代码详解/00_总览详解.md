## 1. 系统是什么

一句话：**用摄像头看人手 → 算出 16 个关节角 → 让 RY-H1(16) 灵巧手复现同样的手势**。

硬件链：

```
人的手
  │  被 L515（RGB + 深度）或 USB 摄像头拍摄
  ▼
Intel L515 / USB 摄像头
  │  输出 RGB 帧（+ 对齐深度帧 + 相机内参）
  ▼
PC（本工程，Python）
  │  MediaPipe 识别 21 个手部关键点 → 结合深度得 3D 坐标 → 解算 16 关节角
  │  → 精度后处理（防抖/限速） → 换算成 16 个电机位置指令
  ▼
RyCAN SDK（RyhandLibx64.dll，厂家提供，ctypes 调用）
  │  CAN / RS485 总线
  ▼
RY-H1(16) 灵巧手（16 个伺服电机）
```

本工程不碰机械臂，只控制灵巧手本体。

## 2. 核心概念：16 个关节与"控制模型"

必须先懂这个，否则看不懂任何代码。

### 2.1 关节 ID（1~16，`hand/hand_config.py`）

| 关节 ID | 含义 | 角度范围 |
|---|---|---|
| 1 | 拇指侧摆 | ±20° |
| 2 | 拇指近节(MCP) | 0~90° |
| 3 | 拇指远节(PIP) | 0~75° |
| 4/7/10/13 | 食/中/无名/小指 侧摆 | ±20° |
| 5/8/11/14 | 食/中/无名/小指 近节 | 0~90° |
| 6/9/12/15 | 食/中/无名/小指 远节 | 0~75° |
| 16 | 第16关节（拇指内外展） | 0~110° |

关键点：
- **每指 3 个电机**（`FINGER_MOTOR_IDS`：拇指 1-3、食指 4-6、中指 7-9、无名指 10-12、小指 13-15、第16关节=电机16）。
- 侧摆（θ1）由两个电机**差动**产生，近节弯曲（θ2）由这两个电机**同向**产生——这是理解 `angles2motor.py` 的钥匙。
- 关节 16（拇指内外展）是**独立电机**，范围 0~110°，本工程里"外展→0°、内收→110°"（或按 `thumb_abd_reverse` 反转）。

### 2.2 角度→电机位置换算（`hand/angles2motor.py`，与官方 demo 一致）

```
k  = 4095 / 90
M1 = k · (θ1/2 + θ2)      # 电机1：近节为主 + 侧摆一半（同向）
M2 = k · (−θ1/2 + θ2)     # 电机2：近节为主 − 侧摆一半（反向）→ 两电机差动出侧摆
M3 = (4095/75) · θ3       # 远节独立
M16 = (4095/110) · θ16    # 第16关节独立
```

- `4095 = 2^12 − 1`：12 位 PWM 位置分辨率（0~4095 对应满行程）。
- 90/75/110 分别对应各关节的**满角度范围**（近节 0-90°、远节 0-75°、关节16 0-110°）。
- **左手**（`hand_lr=0`）时，每指 `M1↔M2` 交换（硬件镜像）。

反变换（`motor_cmds_to_joint_angles`，用于"读回当前角度"）：

```
θ1 = (M1 − M2) / k
θ2 = (M1 + M2) / (2k)
θ3 = M3 / K3
θ16 = M16 / K16
```

> 手型选反的典型现象：滑"近节"滑条，实际动的是"侧摆"——这时在 GUI 顶部切"左手/右手"即可。

## 4. 完整数据流（从相机到灵巧手）

```
GUI._capture_loop（后台线程，生产者）
  │  cam.read() → (rgb_bgr, depth)        ← lib/camera_lib1.py
  │       放入 frame_q（容量2，丢旧帧）
  ▼
GUI._poll_video（Tk after(30ms) 轮询，消费者/主线程）
  │  frame_q.get_nowait() → (rgb, depth)
  │  intrinsics = cam.get_intrinsics()    ← 相机内参 {fx,fy,ppx,ppy}
  │  est.process(rgb, depth, intrinsics)  ← vision/hand_pose.py
  │        │   bgr→rgb → MediaPipe HandLandmarker.detect
  │        │   → 21 关键点(归一化) + 左右手标签 + 置信度
  │        │   → 结合深度转 3D 坐标（针孔反投影）
  │        │   → 构建手掌局部坐标系(normal/palm_axis/perp)
  │        │   → 16 关节角(度) + lateral_dist + fist_confidence
  │        ▼
  │  HandResult[]（只取右手）
  │  绘制骨架/角度叠加 → 显示到视频画布（等比缩放+居中裁剪）
  │  info_var 显示关节角/深度/握拳置信/稳定性指标
  │
  │  if mimic_on 且手已连接:
  │        ▼
  │  _mimic_apply(angles_deg, fist_confidence)
  │    ① 5帧均值（去单帧毛刺）
  │    ② deadzone 死区（|角度|<阈值→0，防微颤）
  │    ③ post.update(avg_deg, fist_confidence)  ← vision/postprocess.py
  │        方向一致性异常检测（真实握拳不丢弃）
  │        → 中值滤波(5) → One Euro 平滑 → 分通道限速
  │    ④ 弧度化 → hand.move_joints(angles_rad)  ← hand/hand_controller.py
  │        angles_to_motor_cmds → 16 个电机位置指令
  │        逐电机 RyMotion_ServoMove_Mix(0xAA 力位混合)
  │        → SDK 写回调 → transport.send() → CAN/RS485 → 灵巧手
  ▼
RY-H1(16) 灵巧手运动
```

**上行（回读）方向**：灵巧手应答帧 → `transport._rx_loop` → `_dispatch` → `_on_frame` → `RyCanServoLibRcvMsg` 喂回 SDK → SDK 的 AddListen 回调解析成 `_last_servo_info[mid]` → `check_connection`/`read_joint_angles` 使用。

## 5. 各模块关键逻辑详解（速览，细节看对应文件文档）

### 5.1 `lib/_pathsetup.py` —— 为什么每个入口都要它
直接运行 `python apps/test_hand.py` 时，`sys.path[0]` 是 `apps/`，不是根目录 → `import hand` 失败、`CDLL("RyhandLibx64.dll")` 找不到。解决：入口顶部
```python
sys.path.insert(0, os.path.dirname(os.path.dirname(os.path.abspath(__file__))))
os.chdir(sys.path[0])
```
`_pathsetup.ensure_root()` 是对它的封装（还供 hand 包加载 DLL 时兜底）。

### 5.2 `hand/hand_config.py` —— 配置单点
- 全部常量集中一处，避免魔法数散落。
- `HAND_CONFIG` 里的 `cmd_pos_vel_cur=0xAA`（位置+速度+电流，带载推荐）、`cmd_pos_vel=0xA1`、`cmd_get_status=0xA0` 是下发给电机的指令码。
- `hook_num=40` / `listen_num=33`：SDK 总线内部 Hook/Listen 槽数量（对齐官方 demo）。

### 5.3 `hand/angles2motor.py` —— 换算器
核心是**差动/共模分解**（见 2.2）。所有输出 `_clamp` 到 [0, 4095] 保护电机。`hand_lr=0` 时交换 M1/M2；反变换时**先交换回来再解算**。

### 5.4 `hand/transport.py` —— 三种通信后端
- PCAN：`PCANBasic` 的 `Initialize(PCAN_USBBUS1, PCAN_BAUD_1M)` → `Write/Read`。
- CANalyst-II：`ControlCAN` 的 `VCI_OpenDevice/InitCAN(1Mbps: Timing0=0x00,Timing1=0x14)/StartCAN/Transmit/Receive`。
- RS485：自封装 0xA5 帧（`|0xA5|id_lo|id_hi|len|data|check|`，`check = sum & 0xFF`）。
- 统一收口：接收线程 1ms 轮询 → `_dispatch(can_id, payload)` → 上层 `_on_frame`。

### 5.5 `hand/hand_controller.py` —— 高层控制器
- **ctypes 结构体**布局必须与 SDK 头文件一致（`RyCanServoBusT` 内含 tick 指针、Hook/Listen 指针、写回调函数指针）。
- `_init_bus`：memset 清零 → 填 tick 周期 1000µs → `RyCanServoBusInit`（传入 `_write` 回调，SDK 要发帧时调它）→ 32 个 `AddListen`（16×0xA0 状态 + 16×0xAA 位置速度电流，ID = 伺服ID+256）→ 启动 tick 线程。
- **1ms 节拍**：`self._ticks.value = int(time.time()*1000) % 1000`——SDK 依赖这个 0~999 毫秒计数器。
- `move_joints`：16 关节角 → `angles_to_motor_cmds` → 逐电机 `RyMotion_ServoMove_Mix`（0xAA 力位混合，限电流防堵转）。
- 状态回读解析（`parse_servo_info`）：8 字节 little-endian 位域——status 8bit / position 12bit / velocity 12bit(有符号) / current 12bit(有符号) / tactile 12bit。
- 故障码 11 = **找零告警**：`set_home_mode(mid, 2)` 立即执行一次回零（CMD 0xBE）恢复行程。

### 5.6 `camera/camera_module.py` 与 `lib/camera_lib1.py` —— 相机
- L515 铁律：`pyrealsense2==2.54.2.5684`（2.55+ 移除 L515）；USB3.0 直连；深度流与 RGB 流**分开设分辨率**（默认 depth 1024×768 + RGB 1280×720）；`rs.align(rs.stream.color)` 深度对齐彩色，保证像素一一对应。
- `0x80070005` = Windows 拒绝访问 → **以管理员身份运行**。
- `camera_lib1` 额外提供：`read(return_timestamp=True)` 严格递增毫秒时间戳（MediaPipe LIVE_STREAM 用）、`landmarks_to_3d` 批量把归一化关键点转相机系 3D 坐标（针孔反投影 `X=(u−ppx)·Z/fx`，`Z=depth·0.001`）。

### 5.7 `vision/hand_pose.py` —— 16 关节角解算（工程核心）
1. **手掌局部坐标系**：`wrist→中指MCP` 与 `wrist→小指MCP` 叉积得法线 `normal`；主轴 `palm_axis`（腕→中指MCP 单位化）；横向轴 `perp = cross(normal, palm_axis)`。
2. **侧摆**：手指 MCP 向量投影到手掌平面，与 `palm_axis` 夹角，符号由 `perp` 方向定，封顶 ±20°。
3. **拇指内外展（v3 算法）**：
   ```
   lateral_dist = |dot(拇指TIP − 掌心, perp)|     # 无符号横向距离
   ratio = lateral_dist / palm_w                   # palm_w = |中指MCP − 掌心|（半掌宽标尺）
   abd_ratio = clip((ratio − offset) · gain, 0, 1)
   abd_ratio = 3x² − 2x³                            # 软饱和
   abduction = (1 − abd_ratio) · 110 或 abd_ratio·110（按 reverse）
   ```
   **关键经验**：不用"方向锚定符号判断"（翻掌/手型变化时方向反了会导致输出恒不变），用无符号距离 + GUI 开关控制方向。
4. **弯曲**：向量夹角法（默认）或距离比率法（`use_distance_ratio`）；叠加全局/每指校准参数（scale/offset/gain）、死区、范围裁剪。
5. **深度辅助握拳置信度 `_compute_fist_confidence`**（新）：四指指尖到掌心 3D 距离 ÷ 半掌宽，张开≈2~3→0，握拳≈0.7~1.1→1.0（映射区间 [0.9,1.6]）。供后处理判断"真实握拳 vs 抖动"，是解决"握拳卡住"的关键输入。

### 5.8 `vision/postprocess.py` —— 精度后处理链（稳定性核心）
```
原始 16 关节角(度)
  → 方向一致性异常检测：jump_max vs jump_med 比值（孤立突变才抑制，真实握拳不丢）
  → 中值滤波(5帧)        去单通道毛刺
  → One Euro 平滑        min_cutoff 越小越平滑；beta 越大越跟手
  → 分通道限速            关节16 用 abduct_max_delta(3°/帧)，其余 max_delta(8°/帧)
  → 稳定输出
```
- **为什么握拳不卡了**：旧版"整帧跳变>20° 就丢弃"会把握拳（0→70° 快速协调运动）误判；新版用**方向一致性**——真实握拳时所有手指同向大跳变（jump_med 也大，比值≈1）不判异常；只有某关节孤跳（比值>3 且 >40°）才抑制，且用中值替代而非整帧丢弃。
- **fist_confidence ≥ 0.6 时直接跳过异常判定**（深度确认真实握拳，双保险）。

### 5.9 `gui/main_gui.py` —— 把一切串起来
- **生产者-消费者**：`_capture_loop` 线程读帧入 `frame_q`（容量 2，满了丢旧帧保持实时）→ `_poll_video` 用 `root.after(30)` 定时取帧处理（Tk 必须主线程刷新 UI）。
- **视频显示**：等比缩放 + 居中裁剪——`scale = max(cw/sw, ch/sh)` 放大到填满，再居中裁掉超出部分（无黑边、无变形）。
- **校准体系**：PARAM_CONFIG 滑条 → `_apply_calib()` → `est.update_params(...)`（姿态解算参数）+ `post.update_params(...)`（后处理参数）+ 写 `config/calibration.json` 持久化。
- **动作模仿**：`_mimic_apply` = 5帧均值 → deadzone → `post.update(avg, fist_conf)` → `move_joints(弧度)`。
- 关闭用 `os._exit(0)` 兜底（Tk 多线程退出易挂）。

## 7. 安全与规范（务必遵守，来自手册）

1. 电源 24V / 8A+；**禁止热插拔**（先断电再接）。
2. 带载运动用 **0xAA 限流模式**（`RyMotion_ServoMove_Mix` 传 `max_current`），启动电流 300~500mA。
3. 不要强行掰手指；首次运行建议 `--scale 0.3` 小幅度试。
4. 行程 < 3000 或 status=11（找零告警）→ 先回零（GUI【回零】按钮 / `homing()`），否则幅度小。
5. 侧摆角度被安全限制在 ±20°（`hand_config.ANGLE_RANGE_DEG` + GUI 滑条范围）。

## 8. 常见问题速查

| 现象 | 定位 | 解决 |
|---|---|---|
| 运行脚本找不到包/DLL | 没做路径引导 | 入口顶部加 sys.path + os.chdir（或 `import _pathsetup; ensure_root()`） |
