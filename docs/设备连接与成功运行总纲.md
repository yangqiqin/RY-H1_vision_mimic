## 1. 系统全貌：都有哪些器件、谁控制谁

```
┌─────────────────────────────────────────────────────────────────────────┐
│  器件（硬件）           │  控制它的软件模块            │  通信方式          │
├─────────────────────────┼────────────────────────────┼────────────────────┤
│ RY-H1(16) 灵巧手        │ hand/hand_controller.py    │ CAN(1Mbps)/RS485   │
│ （16 个伺服电机）        │ → RyhandLibx64.dll(SDK)    │ (5Mbps) → PCAN 模块 │
├─────────────────────────┼────────────────────────────┼────────────────────┤
│ Aubo K5 机械臂（6 轴）  │ arm/arm_controller.py      │ 网线 TCP RPC        │
│                         │ → pyaubo_sdk               │ (端口 30004)       │
├─────────────────────────┼────────────────────────────┼────────────────────┤
│ Intel L515 RGB-D 相机   │ lib/camera_lib1.py         │ USB3.0             │
│ （RGB + 深度）           │ → pyrealsense2             │                    │
├─────────────────────────┼────────────────────────────┼────────────────────┤
│ USB 摄像头（可选替代）  │ lib/camera_lib1.py         │ USB（OpenCV）      │
│                         │ → cv2.VideoCapture         │                    │
└─────────────────────────┴────────────────────────────┴────────────────────┘

数据关系（谁给谁数据）：
  L515/USB 摄像头 →(RGB+深度)→ 姿态估计(hand_pose) →(16关节角)→ 后处理(postprocess)
      →(稳定角度)→ 灵巧手控制器 →(电机指令)→ RY-H1 灵巧手
  灵巧手若装在机械臂末端：机械臂(arm) 负责"把末端摆到目标位姿"，灵巧手负责"做手势"
      → TCP 坐标联动（setTcpOffset 写入灵巧手安装偏移）
```

**一句话逻辑**：摄像头"看"人手 → 算出 16 个关节角 → 灵巧手复现手势；
机械臂是"搬运工"，把装在末端的手送到目标位置，再让手做动作。

## 2. 第一部分：器件连接（硬件）

> 依据：《RY-H1(16)灵巧手用户使用手册》V1.0.0 + 遨博官方文档。

### 2.1 RY-H1(16) 灵巧手接线

**发货清单**：灵巧手 ×1、转接底座 ×1、M9 航插线 ×1、PCAN 模块 ×1（与航插线连接）、M3 螺丝配件包 ×1。

**连接步骤**（严格按顺序）：

| 步骤 | 操作 | 作用/为什么 |
|---|---|---|
| ① 固定 | 用 M3 螺丝把灵巧手拧到转接底座（至少 3 颗） | 固定手，防止运动时位移 |
| ② 供电 | 电源 **24V，推荐 10A 及以上**（手册：24V~60V 均可） | 16 电机同时动作电流大，功率不足会复位/无力 |
| ③ 航插 | **先确认电源和信号线接线无误** → 对齐航插头红点 → 轻轻前推到到位 | 防烧主板；红点对齐保证极性正确 |
| ④ 通信 | M9 航插线 → PCAN 模块 → USB 接电脑（或 USB-CAN / RS485 转接） | PCAN 是默认通信方式（1Mbps） |

**通信三选一**：

| 方式 | 硬件 | 波特率 | 需要文件 | 启动参数 |
|---|---|---|---|---|
| PCAN（默认） | Peak PCAN-USB | 1Mbps | `PCANBasic.py` + PCAN 驱动 | `--method pcan` |
| CANalyst-II | 周立功 USB-CAN | 1Mbps | `ControlCAN.py/.dll` | `--method canii` |
| RS485 | 串口（5Mbps 支持） | 5Mbps | `pyserial` | `--method rs485 --port COM3` |

### 2.2 Aubo K5 机械臂连接

| 步骤 | 操作 | 作用/为什么 |
|---|---|---|
| ① 控制柜上电 | K5 控制柜接电源开机 | 控制柜是机械臂的"大脑"（运行 RPC 服务） |
| ② 网线连接 | 电脑网口 ↔ 控制柜网口（直连或同交换机） | RPC 走 TCP，需网络可达 |
| ③ IP 配置 | 电脑与控制柜同网段（如控制柜 `192.168.1.100`，电脑 `192.168.1.100/24`） | 控制柜默认 IP 见示教器；`arm/arm_config.py` 可改 |
| ④ 登录凭据 | 账号 `aubo` / 密码 `123456`（官方示例默认） | RPC 登录 |

> 灵巧手若装机械臂末端：安装偏移（相对法兰）写入 `arm/arm_config.py` 的
> `hand_mount_offset`（TCP 坐标联动），需按实际安装实测。

### 2.3 L515 相机连接

| 步骤 | 操作 | 作用/为什么 |
|---|---|---|
| ① USB3.0 直连 | **必须 USB3.0 口直连，勿经 USB2 集线器** | L515 带宽需求高，USB2 会卡/花屏 |
| ② 装驱动 | Intel RealSense SDK 2.0 运行时 | pyrealsense2 依赖 |
| ③ 固定版本 | `pip install pyrealsense2==2.54.2.5684` | **librealsense 2.55+ 已移除 L515 支持**，装新版识别不到 |
| ④ 权限 | Windows 下以管理员运行 / 允许相机隐私访问 | 否则 `0x80070005 拒绝访问` |

### 2.4 上电顺序总表

```
① 电源与线缆确认无误 → ② 灵巧手 24V 上电 → ③ 机械臂控制柜上电 → ④ 电脑开机
→ ⑤ 运行环境自检(selfcheck.py) → ⑥ 逐个连接验证（先手后臂再相机）
```

> ⚠️ **断电顺序**：先停运动（GUI【停止】/ 机械臂 stopMove）→ 机械臂回安全位 → 断开连接 → 再断电。
> **禁止带电插拔**灵巧手航插；机械臂运动时禁止进入工作半径。

```bash
# ① Python 3.10+ 环境
# ② 安装依赖（视觉 + 灵巧手 + 机械臂）
python -m pip install -r requirements.txt
```

**关键文件必须就位**（自动搜索 根目录 + lib/ + lib/参考代码/）：

| 文件 | 位置 | 缺了会怎样 |
|---|---|---|
| `RyhandLibx64.dll` | `lib/` | 灵巧手控制器无法加载 |
| `PCANBasic.py` + 驱动 | `lib/pcan/`（或 lib/） | `--method pcan` 失败 |
| `hand_landmarker.task` | `lib/` | MediaPipe 姿态估计失败 |
| `pyaubo_sdk`（pip 包） | 已安装 | 机械臂控制失败 |
| `lib/camera_lib1.py`（转发） | `lib/` | GUI 相机失败（它转发 `lib/参考代码/camera_lib1.py`） |

> **目录布局说明**（用户已整理）：`lib/` = 运行必需资源（DLL/模型/SDK 压缩包/转发模块）；
> `lib/参考代码/` = 参考实现归档（camera_lib1.py / L515_driver.py / vision_hand_ctrl.py）；
> `lib/auboDocument/` = 遨博官方文档；`lib/aubo_sdk-*/` = 遨博 SDK 全量（含 31 个 Python 示例）。

## 4. 第三部分：让设备成功运行（启动与验证）

> 原则：**先自检 → 再单项验证 → 最后组合运行**。每步通过再进入下一步，避免"全都不通不知从哪查"。

### 4.1 环境自检
```bash
python selfcheck.py
```
**作用**：不接硬件也能验证依赖、换算、路径引导是否正常。重点关注 `换算 [PASS]`（核心逻辑正确）。

### 4.2 单项验证：灵巧手
```bash
python apps/test_hand.py --method pcan          # 连接性自检（应 >0/16 应答）
python apps/test_hand.py --method pcan --move   # 附带张开/握拳
python apps/diag_motor.py --method pcan --fix-homing   # 若自检有"找零告警(11)"自动回零
```
**每步作用**：`test_hand` 先验证"总线通不通"（16 电机应答数），再验证"动起来"（张开/握拳）。

### 4.3 单项验证：机械臂
```bash
python apps/test_arm.py --ip 192.168.1.100                # 连接 + 读状态（安全）
python apps/test_arm.py --ip 192.168.1.100 --startup --move   # 上电+启动+安全运动
python apps/diag_arm.py --ip 192.168.1.100 --poweron --fk --ik   # 深度诊断（正逆解自检）
```
**每步作用**：先确认 RPC 通（连接+登录+读状态）→ 再上电松刹车 → 小幅度运动验证方向。

### 4.4 单项验证：相机/L515
```bash
python apps/test_camera.py --list                # L515 识别（版本/权限/设备）
python apps/test_camera.py --realsense --show    # 出图验证（RGB+深度）
python apps/diag_camera.py                       # 深度诊断（枚举/组合/连续取帧）
```

### 4.5 组合运行：扩展 GUI
```bash
python -m gui.main_gui_arm
```
**推荐操作流程**（每步作用见括号）：
1. **启动相机**：选 L515 →【启动】（摄像头供视觉数据）
2. **连接灵巧手**：选 PCAN + 左右手 →【连接】→【自检】→【回零】（如有找零告警）
3. **连接机械臂**：填 IP →【连接】→【上电+启动】（等 Running）
4. **速度比例**调 0.2~0.3 →【回初始位】（安全起步）
5. **校准**：看实时关节角，调 bend_gain / 平滑 / 内外展（让角度与实际手势匹配）
6. **动作模仿**：勾选【动作模仿】（摄像头前做手势，灵巧手跟随）
7. **臂手联动**（可选）：勾【TCP联动】→ 填 movel 位姿 →【到位后握拳】（先摆位再抓手）
8. **退出**：关闭窗口（自动断开手与机械臂）

## 5. 第四部分：运行逻辑详解（数据流与每步作用）

### 5.1 完整数据流（相机 → 灵巧手 → 机械臂）

```
┌─ 采集线程（生产者，后台）─────────────────────────────────────────────┐
│  cam.read() → (RGB帧, 深度帧)          ← lib/camera_lib1.py          │
│       │  放入 frame_q（容量2，满则丢最旧帧 → 保持实时性）              │
└───────┼──────────────────────────────────────────────────────────────┘
        ▼
┌─ 主线程轮询（消费者，Tk after 30ms）───────────────────────────────────┐
│  frame_q.get_nowait() → (rgb, depth)                                  │
│  intrinsics = cam.get_intrinsics()   ← 相机内参 {fx,fy,ppx,ppy}       │
│  est.process(rgb, depth, intrinsics)  ← vision/hand_pose.py           │
│      ├─ BGR→RGB → MediaPipe 检测 21 个手部关键点                       │
│      ├─ 结合深度 → 3D 坐标（针孔反投影）                               │
│      ├─ 构建手掌坐标系 → 16 关节角(度) + 深度握拳置信度                 │
│  post.update(avg_deg, fist_confidence)  ← vision/postprocess.py       │
│      ├─ 方向一致性异常检测（真实握拳不丢弃）                           │
│      ├─ 中值滤波 → One Euro 平滑 → 分通道限速                          │
│  hand.move_joints(angles_rad)  ← hand/hand_controller.py              │
│      ├─ angles_to_motor_cmds：16关节角 → 16电机位置(0~4095)            │
│      ├─ 逐电机 RyMotion_ServoMove_Mix(0xAA 限流模式)                   │
│      └─ SDK 写回调 → transport.send() → CAN/RS485 → 灵巧手             │
│  （若机械臂联动）arm.movel(pose) → pyaubo_sdk → K5 控制柜 → 机械臂      │
└───────────────────────────────────────────────────────────────────────┘
        ▼
RY-H1 灵巧手做手势 ／ Aubo K5 机械臂摆位
```

### 5.2 灵巧手控制链路每步作用

| 环节 | 模块/代码 | 作用（为什么必须有） |
|---|---|---|
| ① 取帧 | `lib/camera_lib1.py::read()` | 拿到一帧 RGB + 深度（深度用于 3D 与握拳判定） |
| ② 手部关键点 | `hand_pose.py::process()` | MediaPipe 检测 21 个关键点（手指关节位置） |
| ③ 3D 坐标 | `_convert_landmarks_to_3d()` | 用深度把 2D 像素提升为真实 3D（比纯 2D 稳、幅度真实） |
| ④ 关节角 | `_landmarks_to_angles16()` | 21 点 → 16 关节角度（灵巧手只认角度） |
| ⑤ 握拳置信 | `_compute_fist_confidence()` | 深度确认"真的在握拳"（解决握拳抖动被误判） |
| ⑥ 平滑链 | `postprocess.py::update()` | 去抖/防突跳/不卡手（见 6.3） |
| ⑦ 换算 | `angles2motor.py::angles_to_motor_cmds()` | 角度 → 电机位置指令（灵巧手电机只认 0~4095） |
| ⑧ 下发 | `hand_controller.py::move_joints()` | 逐电机 0xAA 指令，带限流（安全） |

### 5.3 机械臂控制链路每步作用

| 环节 | 模块/代码 | 作用（为什么必须有） |
|---|---|---|
| ① 连接 | `arm_controller.py::open()` | RPC 连接 + 登录 + 缓存子接口（一次连接多次调用） |
| ② 上电启动 | `poweron_and_startup()` | 上电 + 松刹车（机械臂才能被驱动） |
| ③ 设速 | `set_speed_fraction()` | 全局速度比例（安全起步 0.3） |
| ④ TCP 联动 | `apply_tcp_offset()` | 把灵巧手安装偏移写入 setTcpOffset（movel 以手 TCP 为基准） |
| ⑤ 运动 | `movej/movel/movec()` | 关节/直线/圆弧运动（block 阻塞等待到位） |
| ⑥ 状态 | `get_state_summary()` | 读模式/关节角/TCP（GUI 显示 + 安全监控） |
| ⑦ 臂手联动 | GUI `_arm_hand_link()` | movel 到位成功后再让手做动作（顺序保证） |

### 5.4 线程模型（谁在跑、何时跑）

```
GUI 进程
 ├─ 主线程（Tk mainloop）
 │    ├─ _poll_video（after 30ms 轮询：取帧→推理→显示→模仿）
 │    └─ _arm_poll_loop（after 800ms 轮询：刷新机械臂状态）
 ├─ 采集线程（_capture_loop）：只读相机帧入队（生产者）
 ├─ 手控制接收线程（transport._rx_loop 1ms）：收 CAN/RS485 应答
 ├─ 手控制 tick 线程（_rx_loop 1ms）：维护 SDK 毫秒节拍
 └─ 后台释放线程（_stop_thread）：停止相机时后台释放资源
```
**为什么这样分**：Tk 只能在主线程刷新 UI；采集/接收放后台线程避免卡界面；
机械臂状态用 `after(800)` 轮询而非线程（RPC 调用较慢，800ms 足够且不阻塞）。

## 6. 第五部分：关键代码解释（对应数据流各环节）

> 逐函数完整注释见 `docs/代码详解/`（01~13）。这里给"数据流各环节"的精简解释。

### 6.1 角度换算：`hand/angles2motor.py`
**一句话**：把人关节的"角度"翻译成电机能执行的"位置码 0~4095"。

```python
k  = 4095 / 90                       # 近节满程 90° ↔ 位置 4095
M1 = k·(θ1/2 + θ2)                   # 电机1：近节为主 + 侧摆一半
M2 = k·(−θ1/2 + θ2)                  # 电机2：近节为主 − 侧摆一半
M3 = (4095/75)·θ3                    # 远节
M16 = (4095/110)·θ16                 # 第16关节（内外展）
```
- **为什么 M1/M2 这样写**：侧摆是"差动"（两电机反向差），近节是"共模"（两电机同向和）；
  除以 2 保证纯侧摆时近节分量抵消。
- **4095 是什么**：12 位 PWM 位置分辨率（2¹²−1），电机位置满量程。
- **左手**（hand_lr=0）：每指 M1↔M2 交换（硬件镜像）。

### 6.2 姿态解算：`vision/hand_pose.py`
**一句话**：把 MediaPipe 的 21 个手部关键点变成 16 个关节角度。

```python
# 手掌局部坐标系（3 个正交轴）
normal    = cross(中指MCP-腕, 小指MCP-腕)   # 手掌法线（垂直掌面）
palm_axis = (中指MCP-腕) 单位化              # 手掌主轴（沿手指方向）
perp      = cross(normal, palm_axis)        # 手掌横向轴
# 侧摆 = 手指向量投影到掌面后与 palm_axis 的夹角（封顶 ±20°）
# 内外展 v3：
lateral = |dot(拇指TIP-掌心, perp)|          # 无符号横向距离
ratio   = lateral / |中指MCP-掌心|           # 除以半掌宽（尺度不变）
abd     = (1-ratio·gain) · 110               # 映射到 0~110°
```
- **为什么用 3D 坐标**：MediaPipe 的 z 是相对深度，不是真实 3D；用 L515 深度反投影更准。
- **为什么内外展无符号**：翻掌时方向会反，自动符号判断会导致输出恒不变（历史 bug）。

### 6.3 精度后处理：`vision/postprocess.py`
**一句话**：让角度"稳"——去抖动、防突跳、握拳不卡。

```python
update(angles_deg, fist_confidence):
  ① 方向一致性异常检测：jump_max vs jump_med 比值
     真实握拳（协调运动）比值≈1 → 不丢弃
     孤立单指突变（比值>3 且 >40°）→ 中值替代（不整帧丢）
  ② 中值滤波(5帧)      → 去单通道毛刺
  ③ One Euro 平滑      → min_cutoff 越小越平滑；beta 越大越跟手
  ④ 分通道限速          → 关节16 用 3°/帧，其它 8°/帧
  fist_confidence≥0.6（深度确认握拳）→ 跳过异常判定（绝不卡住）
```

### 6.4 灵巧手控制器：`hand/hand_controller.py`
**一句话**：通过 ctypes 调厂家 RyCAN SDK 驱动 16 电机。

```python
_init_bus():  # 对齐官方 demo
  hook=40, listen=33                       # 总线内部槽数量
  32×AddListen（16×0xA0 状态 + 16×0xAA 运动，ID=伺服ID+256）
  1ms 节拍：ticks = time.time()*1000 % 1000   # SDK 依赖的毫秒计数器
move_joints(angles_rad):
  cmds = angles_to_motor_cmds(...)          # 角度→位置码
  逐电机 RyMotion_ServoMove_Mix(0xAA)       # 0xAA=位置+速度+电流（限流，带载安全）
```
- **故障码 11** = 电机找零告警（未回零、行程受限）→ GUI【回零】执行 homing（CMD 0xBE）。

### 6.5 机械臂控制器：`arm/arm_controller.py`
**一句话**：用 pyaubo_sdk 的 RPC 控制 Aubo K5 六轴机械臂。

```python
open():  connect(ip, 30004) → login("aubo","123456")
         → getRobotInterface → 缓存 6 个子接口（Manage/Motion/State/Config/IO/Algorithm）
movej(q):  moveJoint(q, vel_rad, acc_rad, blend, 0)  # 关节运动（弧度）
movel(p):  moveLine(p, vel, acc, blend, 0)           # 直线（TCP 系，米/弧度）
_wait_arrival():  getExecId -1=等开始 → 非-1=等完成（带 30s 超时）
apply_tcp_offset():  setTcpOffset(基础+安装偏移)     # TCP 坐标联动
```
- **弧度还是度**：关节角用弧度（`math.radians` 转换）；位姿 [x,y,z,rx,ry,rz] 位置米、姿态弧度。
- **速度比例**：`setSpeedFraction(0.3)` 全局减速（安全），官方示例 0.75。

### 6.6 主 GUI：`gui/main_gui_arm.py`
**一句话**：把相机/姿态/后处理/灵巧手/机械臂全部串起来的界面。

```python
class MainGuiArm(MainGui):        # 继承原灵巧手 GUI（不改原文件）
  _build_arm_ui():                # 底部新增机械臂面板（连接/电源/6轴滑条/movel/联动）
  _arm_poll_loop():               # after(800) 常驻刷新机械臂状态
  _arm_hand_link(动作):           # movel 到位成功 → hand.close_hand/open_hand/relax
  _on_close():                    # 先断机械臂 → super()._on_close()（原逻辑会 os._exit(0)）
```

## 7. 第六部分：关键名词精简解释（术语表）

|---|---|
| **关节 ID 1~16** | 灵巧手 16 个自由度编号：1 拇指侧摆、2/3 拇指近/远节、4~15 四指(侧摆/近节/远节)、16 拇指内外展 |

| **找零/回零(homing)** | 电机建立位置基准；未回零 → status=11 → 行程受限、动作小 |
| **行程(Stroke)** | 电机可动范围（应≈4095）；<3000 说明受限 |
| **TCP** | 机械臂工具中心点（末端执行器坐标系，即灵巧手所在处） |
| **TCP 偏移/联动** | 告诉机械臂"工具(手)相对法兰偏了多少"，movel 以手为基准 |
| **movej/movel/movec** | 机械臂三种运动：关节运动 / 直线 / 圆弧 |
| **servoJoint** | 关节伺服：高频(5ms)下发目标点，视觉实时跟随用 |
| **freedrive** | 拖拽示教：机械臂松刹车可手拖 |
| **RPC** | 远程过程调用（机械臂 SDK 的通信方式，TCP 30004 端口） |

## 8. 第七部分：全部注意事项（安全与正确性）

### 8.1 安全红线（必读）
1. **航插安全**：插 M9 航插前**必须先确认电源和信号线接线无误**，对齐红点轻推到到位；
   **切勿未确认就插入或上电**（可能烧主板）。
2. **禁止带电插拔**灵巧手航插；航插裸露线**必须用电工胶布包裹**（防短路烧板）。
3. **供电**：灵巧手 **24V / 10A 及以上**；功率不足会复位/无力。
4. **不要用力掰手指**（腱绳结构会崩线）；手指附近运行时不要站人。
5. **机械臂**：上电/运动前确认周围无人、无障碍物、急停可触及；首次速度 0.2~0.3。
6. **L515**：USB3.0 直连；版本必须 2.54.2.5684；Windows 以管理员运行。
7. **带载运动**用 0xAA 限流模式，电流 300~500mA 起步；过温过流冷却 5 分钟再试。

### 8.2 操作规范
- 运动前先 `selfcheck.py` + 单项验证，确认方向与幅度，`--scale 0.3` 起步；
- 状态 11（找零告警）先回零再操作；
- 行程 <3000 用 `set_stroke(mid, 4095)` 恢复（先读当前值，谨慎）；
- 机械臂断电前：停止 → 回安全位 → 断开 → 断电；
- 修改 `arm/arm_config.py` 的 IP/安装偏移后重启 GUI 生效。

### 8.3 易错点清单
| 现象 | 原因 | 处理 |
|---|---|---|
| 滑"近节"实际动"侧摆" | **手型选反** | GUI 切"左手/右手"（立即生效） |
| 动作幅度小/看不见 | 找零告警(11)/行程小 | 【回零】→ 查行程 |
| L515 识别不到 | 版本>2.55 / USB2 / 权限 | 装 2.54.2.5684 / USB3 / 管理员 |
| 握拳卡住（旧版） | 整帧丢弃误判 | 已修复（方向一致性+深度确认）；用最新 postprocess |
| 内外展跳变快 | 限速过粗 | 调小"内外展限速°/帧"（1.5~2.0） |
| 机械臂连接失败 | IP/端口/网络/登录 | ping 控制柜；核对 IP/账号；控制柜开机 |
| 机械臂不动 | 未上电/未启动/速度=0 | poweron_and_startup；速度比例>0 |
| movel 奇异点/不可达 | 位姿超工作空间 | 改 movej（关节角）；减小位姿变化 |
