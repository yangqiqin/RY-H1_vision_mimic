## 1. 总体思路

之前的方案只用 `hand_landmarker.task`（手部模型）识别手 → 只控制灵巧手，**缺少"人体位置"信息**，
机械臂无法知道"手在哪里、该往哪摆"——这就是你说的"定位中存在错误"。

新方案引入 **MediaPipe Holistic 全身模型**（`lib/holistic_landmarker.task`，最新版，mediapipe 1.0.1 已验证）：

```
┌──────────────────────────────────────────────────────────────────────────┐
│  L515 摄像头（RGB + 深度 + 内参）                                         │
│      │                                                                   │
│      ▼                                                                   │
│  MediaPipe HolisticLandmarker（一帧一次推理）                             │
│      ├─ pose_landmarks       人体 33 关键点（肩/肘/腕/髋…）→ 机械臂定位     │
│      ├─ left/right_hand      手部 21 关键点 → 灵巧手 16 关节角             │
│      └─ pose_world           人体世界坐标（可选用）                        │
│      │                                                                   │
│      ├──────────────┬──────────────────────────────┐                     │
│      ▼              ▼                              ▼                     │
│  腕部 3D     手部 21 点                         16 关节角                 │
│      │              │                              │                     │
│      ▼              ▼                              ▼                     │
│  ArmFollower   hand_pose 解算链              postprocess 平滑            │
│  映射为 TCP      （复用 hand_pose）             → 灵巧手 move_joints      │
│      │                                                                   │
│      ▼                                                                   │
│  机械臂 movel/servo 跟随（人动臂动）                                      │
└──────────────────────────────────────────────────────────────────────────┘
```

**一句话**：**人体手臂的移动 → 机械臂跟着动；人手的手势 → 灵巧手跟着做**。

## 2. 为什么用 Holistic（解决"定位错误"）

| 问题 | 旧方案（仅手部模型） | 新方案（Holistic） |
|---|---|---|
| 机械臂不知道目标位置 | 手部模型只给手的相对位置，无"人体在哪" | 人体 33 点给出肩/肘/腕 3D → 可映射机械臂 TCP |
| 人动臂不动 | 无联动 | 腕部 3D → TCP 目标，机械臂跟随 |
| 手部检测不稳定 | 手部模型在整图找手，易被干扰 | Holistic 全身先定位，手部在人体附近找，更稳 |
| 定位存在错误 | 2D 归一化坐标 → 幅度/位置失真 | 深度 3D + 世界坐标 → 米制真实位置 |

**关键**：L515 深度帧把 2D 关键点提升为真实 3D（针孔反投影），Holistic 的 `pose_world_landmarks`
还提供尺度一致的世界坐标——这些都是"定位正确"的基础。

## 3. 数据流与模块划分

```
vision/holistic_pose.py      HolisticPoseEstimator：检测人体+双手 → HolisticResult
  ├─ pose_landmarks(33,3)     人体关键点（归一化）
  ├─ pose_3d(33,3)            人体关键点 3D（相机系米制）
  ├─ wrist_3d[3]              所选手腕 3D（机械臂映射用）
  ├─ hand_landmarks(21,3)     手部关键点（归一化）
  ├─ hand_angles_deg[16]      16 关节角（复用 hand_pose 解算链）
  ├─ hand_fist_confidence     深度握拳置信度
  └─ arm_target_pose[6]       映射后的机械臂 TCP 目标

arm/arm_follow.py             ArmFollower：腕部 3D → TCP [x,y,z,rx,ry,rz]
  ├─ map_wrist_to_arm_pose()  纯计算映射（可单独验证）
  ├─ update_calib()           运行时改标定参数
  └─ estimate_pose_from_arm() 可选：肩→肘方向估姿态

gui/main_gui_holistic.py      MainGuiHolistic(MainGuiArm)：协同总 GUI
  ├─ 继承：灵巧手全部 + 机械臂面板 + TCP/臂手联动
  └─ 新增：协同面板（检测开关/跟随开关/标定参数/状态显示）
```

**不改动**：`vision/hand_pose.py`、`gui/main_gui.py`、`gui/main_gui_arm.py`、`hand/`、`camera/` 原文件。
（`arm/arm_config.py` 只更新了 `hand_mount_offset` 实测值，属机械臂相关允许修改。）

## 4. 协同映射逻辑（核心）

### 4.1 手 → 灵巧手（16 关节角）
Holistic 输出的手部 21 点（归一化）→ 复用 `hand_pose.py` 的解算链：
```
_convert_landmarks_to_3d(21点, 深度, 内参) → 米制 3D
_landmarks_to_angles16(3D) → 16 关节角（侧摆/近节/远节/内外展，全校准链）
_compute_fist_confidence() → 深度握拳置信度
```
**为什么复用 hand_pose**：保证与纯手部方案的角度语义、校准参数完全一致（同一套
bend_gain / per_finger / thumb_abd 等），GUI 校准面板通用。

### 4.2 人体腕部 → 机械臂 TCP（ArmFollower）
```
坐标系链：L515 相机系(米) --外参--> 机械臂基座系 --安装偏移--> TCP 系
映射公式：target_i = (wrist_i - offset_i) * scale_i + add_i   （i = x,y,z）
姿态：    固定朝下抓取姿态 [π, 0, 0]（或按肩→肘方向估）
安全：    target 裁剪到 [min_xyz, max_xyz]（防越界猛动）
```
- `offset`：相机系原点相对机械臂基座的平移（米）；
- `scale`：各轴缩放（通常 1.0）；
- `add`：目标附加平移（把"人前"映射到"臂前"）；
- **默认参数是经验值，必须现场标定**（见 §7）。

### 4.3 TCP 坐标联动（与协同叠加）
机械臂的 `movel` 位姿默认以法兰为基准；勾选 TCP 联动后，`setTcpOffset` 写入
**实测安装偏移**（`lib/auboDocument/tcp.md`，已更新到 `arm/arm_config.py`），
此后 movel 的坐标直接以"灵巧手 TCP"为基准——协同映射的目标位姿即手爪目标位。

### 4.4 跟随控制
- **机械臂跟随**：每帧把 `wrist_3d` 映射为 TCP → `arm.movel(pose, block=False)`（非阻塞，持续跟随）；
- **灵巧手跟随**：每帧 `hand_angles_deg` → `hand.move_joints(rad)`（独立于原 mimic 开关，防双重下发）；
- 两者独立开关，可只跟臂、只跟手或都跟。

## 6. 协同总 GUI 使用

```bash
python -m gui.main_gui_holistic
```

**界面层次**（自下而上）：
1. 原灵巧手界面（相机/手控/校准/动作模仿）
2. 机械臂面板（连接/电源/6轴/movel/TCP联动/臂手联动）
3. **协同控制面板**（第 5 行）：
   - `启用 Holistic 检测`：启动模型（需先启动相机，L515 最佳）
   - `机械臂跟随(腕→TCP)`：勾选后腕部驱动机械臂 movel
   - `灵巧手跟随(手→16角)`：勾选后手势驱动灵巧手
   - 手：右/左 选择
   - 标定参数：offset/scale/add 输入框 + `应用标定`
   - 状态显示：人体/手/腕3D/臂TCP/握拳置信度

**推荐流程**：
```
① 启动相机(L515) → ② 连接灵巧手 → ③ 连接机械臂 + 上电启动
④ 协同面板：勾选【启用 Holistic 检测】→ 看状态显示是否有人体/手
⑤ 先用 --selfcheck 验证映射方向 → 标定 offset/add（见 §7）
⑥ 速度比例 0.2 → 勾选【机械臂跟随】试小范围 → 确认方向正确再加大
⑦ 勾选【灵巧手跟随】→ 做手势看手跟随
⑧ 退出：关闭窗口自动全部断开
```

## 7. 标定流程（重要）

映射参数（offset/scale/add）**必须现场标定**，否则机械臂位置会偏：

```
方法一：两点标定（推荐起步）
  ① 人站在相机前约 1m，把手腕放在一个期望位置（如胸前 30cm）
  ② 记下 GUI 显示的 腕3D (wx,wy,wz)
  ③ 用示教器把机械臂手动移到"希望手爪到达的位置"，记下 TCP (tx,ty,tz)
  ④ 计算 offset_i = wx_i - tx_i / scale_i（scale 先取 1）→ 填入 offset
  ⑤ add 用于微调：手腕移远/近时目标应跟随，偏差用 add 补

方法二：三点标定（更准）
  左/中/右三个位置分别记录 (腕3D, 实际TCP)，解出 scale + offset

方法三：手眼标定（最准，进阶）
  用标定板做相机↔机械臂外参标定（参考 OpenCV calibrateHandEye）
```

**验证**：标定后，人慢慢移动手腕，机械臂应平滑跟随且末端接近期望位置；
若反向 → 检查相机安装方向与坐标轴符号；若幅度不对 → 调 scale/add。

## 8. 安全与注意事项

1. **协同控制会移动机械臂**！首次务必：速度比例 0.2、`--selfcheck` 验证映射、周围无人、急停可触及；
2. **先标定再跟随**：未标定的 offset/add 会导致机械臂乱跑，禁用"机械臂跟随"直到标定完成；
3. **双重下发防冲突**：勾选【灵巧手跟随】时，**不要同时勾选原【动作模仿】**（两路都发指令会打架）；
4. **机械臂跟随用非阻塞 movel**：GUI 主线程每帧调用，若机械臂忙会丢帧，属正常（下一帧再跟）；
5. **L515 优先**：深度 3D 是定位正确的基础；纯 USB 相机无深度时 3D 用相对 z 补全，精度下降；
6. **Holistic 手部侧别**：`手: 右/左` 应与实际使用的手一致（Holistic 的左右手是相机视角的镜像，可能需要反选）；
7. **灵巧手安全范围**：手势仍受 16 关节角度范围约束（侧摆 ±20° 等），不会越界；
8. 模型加载约 1~2 秒，启动后不要重复点击【启用】。

## 9. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 模型加载失败 | `holistic_landmarker.task` 不在 lib/ | 放到 lib/；下载地址见 `holistic_pose.MODEL_DOWNLOAD_URL` |
| 检测不到人体 | 距离太远/姿态侧对 | 站到相机前 0.8~2m，正面朝相机 |
| 手腕 3D 为 None | 深度无效/人体未检测 | 用 L515；确认深度有值 |
| 机械臂乱跑 | 未标定 / 映射反向 | 先 `--selfcheck`；重新标定；检查坐标符号 |
| 机械臂不跟随 | 未勾选跟随 / 未连接 / 未上电 | 检查三条件；看状态显示"臂TCP"是否有值 |
| 灵巧手不跟随 | 未勾选 / 与 mimic 冲突 | 只勾【灵巧手跟随】，关掉【动作模仿】 |
| 左右手反了 | Holistic 镜像 | 切换"手: 右/左" |
| 帧率低 | holistic 模型较慢 | 降低分辨率；用 GPU 机型；关闭骨架绘制 |
