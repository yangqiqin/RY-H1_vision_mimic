## 1. 总体方案（眼在手上是什么）

**眼在手上（eye-in-hand）**：相机（L515）固定在机械臂末端，随末端一起运动。
相机"看到"人的手 → 识别手腕中心 + 手部关节 → 经**手眼标定**换算到机械臂基座系 →
驱动机械臂（手腕下移→末端下移）+ 灵巧手（手势→动作模仿）。

```
┌─────────────────────────────────────────────────────────────────────┐
│  L515（固定在机械臂末端，随末端运动）                                  │
│    │ RGB + 深度                                                      │
│    ▼                                                                 │
│  HolisticLandmarker（vision/holistic_pose.py）                       │
│    ├─ 人体 33 点 → 手腕 3D（相机系）     → 机械臂跟随                 │
│    └─ 手部 21 点 → 16 关节角             → 灵巧手动作模仿             │
│    │                                                                 │
│    ▼                                                                 │
│  vision/hand_eye.py（手眼标定）                                      │
│    相机系 → 末端法兰系（标定矩阵）→ 基座系（当前末端位姿）             │
│    │                                                                 │
│    ▼                                                                 │
│  arm/arm_follow_eye.py（跟随控制）                                   │
│    增量（Δ手腕）→ 限幅(5mm/帧) → 高度安全区检查(z) → 锁腕IK/FK校验 → movej   │
│    │              └── 丢失手 → 立即 stop_move（急停）                │
│    ▼                                                                 │
│  Aubo K5 机械臂末端（相机+灵巧手）相对运动                            │
└─────────────────────────────────────────────────────────────────────┘
```

**关键设计**：
- **末端固定姿态 + 末端三关节锁腕**：跟随中末端世界系姿态 RPY 固定（不随运动变）；
  目标点一律以【腕关节 J4/J5/J6 钉在锁定角】的 IK/FK 校验后 movej 执行——末端三个
  关节在运动中几乎不动（偏差 ≤ 软容差 3°，GUI 可调），杜绝 SDK 笛卡尔插值偷偷转腕、
  把相机/灵巧手（装在第 6 关节上）方向带偏；
  把相机/灵巧手（装在第 6 关节上）方向带偏；
- **相对增量跟随**：手腕下移多少 → 末端下移多少（不是绝对定位）；
- **高度安全区（z）**：限制末端高度（基坐标系 z，xy 不计入），防相机/灵巧手撞桌面/升太高；
- **失手急停**：连续 N 帧检测不到手 → **立即强制停止机械臂**（安全红线）。

## 3. 每个模块的作用与数据需求

### 3.1 `vision/hand_eye.py` 手眼标定模块

**作用**：把相机坐标系下的点（手腕/物体）转换为机械臂基座坐标系下的点——
这是"眼在手上"的**核心坐标翻译官**。

**数据需求**：
| 数据 | 来源 | 说明 |
|---|---|---|
| `R_cam2gripper`（3x3 旋转矩阵） | `lib/grasp` 标定结果（CALIB） | 相机系→末端法兰系旋转 |
| `t_cam2gripper`（3, 平移向量） | 同上 | 相机系→末端法兰系平移（米） |
| 相机内参 fx/fy/ppx/ppy | L515（DEFAULT_INTRINSICS） | 像素→相机系 3D |
| 机械臂当前末端位姿 | `arm.get_tcp_pose()` | 末端法兰系→基座系 |

**4 层坐标转换**（与 grasp 的 nanning.py 一致）：
```
① 像素(u,v)+深度Z → 相机系：  P_cam = [(u-cx)/fx·Z, (v-cy)/fy·Z, Z]
② 相机系→末端法兰系：        P_gripper = R_cam2gripper·P_cam + t_cam2gripper
③ 读当前法兰位姿：            end_pos + R_gripper2base（正运动学/当前位姿）
④ 末端法兰系→基座系：        P_base = R_gripper2base·P_gripper + end_pos
```

**方法**：
- `pixel_to_camera(u, v, depth_mm, intrinsics)`：①
- `camera_to_base(P_cam, arm)`：②+③+④（最常用，输入相机系 3D 点）
- `pixel_to_base(u, v, depth_mm, intrinsics, arm)`：①→④ 全链路
- `set_calibration()`：运行时换标定矩阵（GUI"切换备用标定"）

### 3.2 `arm/arm_safety.py` 高度安全区模块（z 轴单向，基坐标系）

**作用**：限制末端**高度（z）**，防碰撞桌面/障碍物或升太高。模块名保留 Box 仅为兼容。

**★ 坐标系与维度设计（用户明确，务必遵守）**：
- 坐标系基准：**无意外一律使用基底（基座）坐标系**；
- **安全框只取 Z（高度）轴**：`xy` 是相对基座的水平面坐标，机械臂末端跟随手/转向到
  不同方位时，基坐标系下的 xy 数值会大幅变化——拿 xy 固定区间当"安全框"会在
  "末端明明安全"时报越界，非常荒谬 → **xy 不计入安全框**；
- 基坐标系 z 与"离桌面/地面高度"方向一致，z 区间：
  `z < min_z` → 防撞桌面；`z > max_z` → 防升太高；
- 末端碰撞盒（SDK `addCollisionBox`）以**末端坐标系**为准，属另一套机制（见 7.6）。

**数据需求**：
| 数据 | 默认值 | 说明 |
|---|---|---|
| `min_z` | 0.18 m | 高度下限（基坐标系 z，防碰桌面） |
| `max_z` | 0.68 m | 高度上限（防升太高） |

> 默认值参考 grasp 项目（SPACE_MIN_Z=0.18, SPACE_MAX_Z=0.68），
> **现场必须按实际工作台/桌面高度修改**（GUI 可调，单位米）。

**方法**：
- `check_pose(pos, margin)`：只看 `pos[2]`（z）是否在区间内（margin 米）→ (ok, 说明)
- `check_path(start, end, margin)`：路径 z 全程检查
- `clamp_pose(pos)`：把 z 裁剪进区间，**x/y 保持不变**
- `set_box(min_z, max_z)` / `get_box()` / `get_zone()`：设置/读取高度安全区
  （set_box 返回是否成功；cm 量级误用/上下限颠倒被拒绝）

**单位约定（★ 全链路唯一单位 = 米，禁止 cm/毫米混用）**：
- 高度安全区 min/max_z、末端读数 `get_flange_pose()[2]` 均为【米】（基坐标系）；
- GUI 输入/实时诊断行直接用米（默认 0.18 ~ 0.68），无隐藏换算；
- 误填 cm 数值（如 50 应填 0.50）会被 `set_box()` 单位防线拒绝并弹窗提示。

**读数防御**（防止"末端明明安全却报越界"的荒谬误报）：
- z 读数 NaN/Inf/超物理范围（[-1,3]m）/长度不足 → 报【读数异常】，不当作越界；
- `arm_controller` 的 `get_flange_pose()/get_tcp_pose()/get_joint_positions()` 均做
  合理性校验（有限值 + 物理范围），异常返回 None → 上层按"读不到"处理、禁止运动。

**GUI 实时诊断行**（【眼在手上控制】→ 高度安全区面板下方，连接机械臂后自动刷新）：
```
末端z=0.450m 高度安全区z[0.18,0.68]m → 区内 ✓ / 区外 ✗ z低于下限(0.050m<0.180m)
```
- 只看 z，x/y 任意变化不影响判定；
- 若怀疑误报：先看这行的【末端z】与区间，确认区间已覆盖当前高度再开始跟随；
- 开始跟随时若末端 z 已在区外 → GUI 弹窗预警，可取消后先调区间；
- 跟随中拦截消息附带 末端z/目标z/高度安全区 诊断数据。

### 3.3 `arm/arm_follow_eye.py` 跟随控制器

**作用**：实现"手腕下移 → 末端下移"的实时增量跟随，含安全保护。

**数据需求**：
| 数据 | 默认 | 说明 |
|---|---|---|
| 手腕相机系 3D | 每帧 | 来自 Holistic（`r.wrist_3d`） |
| `max_step_m` | 0.005 m/帧 | 单帧最大位移（防猛冲） |
| `lost_frames` | 5 帧 | 连续丢手触发急停 |
| `fixed_rpy` | 跟随启动时实测法兰姿态 | 固定末端姿态（世界系方向基准） |
| `max_speed` | 0.15 m/s | 运动速度上限（仅 cartesian 模式） |
| `cam_still_m` | 0.008 m | 相机系静止阈值（手没动→绝不下发） |
| `motion_mode` | "wrist_lock" | **锁末端三关节（默认）** / "cartesian"（旧笛卡尔） |
| `wrist_tol_deg` | 3.0°（软容差） | 腕差 ≤ 此值直接跟随（腕几乎不动） |
| `wrist_hard_deg` | 15.0°（硬限） | 缩步到最小仍需转腕 > 此值才判定不可达（奇异/边界）→ 计数 |
| `wrist_unreach_frames` | 8 帧 | 连续"锁腕硬不可达"触发急停 |

**处理流程**（每帧，默认 `wrist_lock` 模式）：
```
update(wrist_3d_cam):
  ① 安全检测：力矩超阈值 / 运动停滞 / 实际姿态偏离 fixed_rpy>2° → 急停
  ② 丢手检测：wrist_3d_cam 为 None → 计数；≥lost_frames → hard_stop 急停
  ③ 相机系窗口防抖：单帧跳变≥阈值 或 窗口累计位移≥阈值 → 判"手在动"（微抖不跟，坏点忽略）
  ④ 锚点追位：期望目标 = 锚点末端 + (手腕基座当前 − 锚点手腕基座)（3D，基座系，幅度1:1）
  ⑤ 追赶步：每帧 ≤ max_step(5mm)；手停后持续追赶直到到位——位移不丢失
  ⑥ 高度安全区(z)检查：期望点与路径 z（xy 不计入）；越界→计数→急停
  ⑦ 【锁腕运动】IK 逆解：参考角把腕钉在锁定角 [J4,J5,J6] → 目标位姿
       → 两级腕差判定 → FK 正解校验位置误差 ≤ 2mm → movej 下发
       腕差≤软容差(3°)直接走；≤硬限(15°)取最小腕差解缩步软降级继续；
       >硬限(奇异/翻转方向)才计数，连续 wrist_unreach_frames 帧 → 急停
```

**锁腕运动详解**（用户核心设计，解决"SDK 偷偷转末端关节导致设备方向被带偏"）：
- **为什么不用 moveLine**：moveLine 笛卡尔插值到达目标时，SDK 常不自觉调用末端三个关节
  （J4/J5/J6）分摊位移 → 相机/灵巧手（装在第 6 关节上）方向被带偏，姿态固定失败；
- **锁腕怎么做**：`begin()` 先读当前关节角，把 `[J4, J5, J6]` 锁为固定值；每帧以
  "当前关节角但腕=锁定值"为 IK 参考初值，求出**末端三关节几乎不动**又能到达目标
  （位置=当前+增量、姿态=fixed_rpy）的整组关节角，再用 FK 正解校验该解确实落在目标上，
  最后 `movej` 下发——**设备方向由 IK 目标位姿（世界系固定姿态）保证绝对不变**；
- **两级容差（修复"0.5°太敏感→无法跟随"）**：
  ① 腕差 ≤ 软容差（默认 3°，GUI 可调 0.1~15）→ 直接跟随（腕几乎不动）；
  ② 软容差 < 腕差 ≤ 硬限（默认 15°）→ 缩步并取最小腕差解**软降级执行**（不阻塞跟随，
     状态显示"腕补偿 x°"）——腕关节的中等调整是"保持世界姿态"的物理必要，
     **不会改变设备方向**（方向由 IK 目标=fixed_rpy 保证）；
  ③ 缩步到最小仍需转腕 > 15°（接近奇异/翻转）→ 计数，连续 `wrist_unreach_frames`
     帧 → **急停**（不通过大幅转动末端关节硬凑目标点）。

**安全红线**：**丢失手 → 立即强制停止**（`stop_move()`），这是防止"机械臂失去视觉信息仍运动"的关键。

## 5. 需要哪些操作（使用流程）

```
① 硬件：L515 USB3.0 连电脑；机械臂上电+网线；灵巧手 PCAN 连接
② 启动：python -m gui.main_gui_eye
③ 相机：选 L515 → 启动（确认出图）
④ 灵巧手：PCAN → 连接 → 自检 → 回零
⑤ 机械臂：IP(192.168.1.100) → 连接 → 上电+启动
⑥ 协同面板：启用 Holistic 检测（确认检测到人体/手）
⑦ 眼在手上面板：
   a. 确认手眼标定参数（默认用 grasp 标定值，或切换备用）
   b. 回初始位 / 记录当前为初始位（固定相机+灵巧手姿态）
   c. 设置高度安全区 z（按桌面高度，单位米）
   d. 设限幅（建议 3~5mm/帧）+ 速度 0.2
   e. ▶ 开始跟随
⑧ 操作：手在相机前做动作 →
   手势 → 灵巧手模仿；手腕下移 → 机械臂末端下移
⑨ 停止：⏹ 停止跟随（急停）或直接关窗
```

## 6. 关键名词解释

| 名词 | 精简解释 |
|---|---|
| **眼在手上 eye-in-hand** | 相机固定在机械臂末端，随末端运动（vs 眼在手外） |
| **手眼标定** | 求相机系↔末端法兰系的旋转矩阵 R + 平移 t（把相机看到的点换算到机械臂坐标系） |
| **R_cam2gripper / t_cam2gripper** | 相机系→末端法兰系的旋转矩阵/平移向量（核心标定结果） |
| **基座系** | 机械臂基座为原点的坐标系（运动指令的参考系） |
| **末端法兰系** | 机械臂末端安装法兰的坐标系（相机/灵巧手装在这里） |
| **TCP** | 工具中心点（末端执行器参考点） |
| **增量跟随** | 每帧算手腕位移增量，累加到机械臂目标（相对运动，非绝对定位） |
| **单帧限幅** | 每帧最大位移（如 5mm），防视觉噪声导致猛冲 |
| **高度安全区（原"安全框"）** | 只按基坐标系 **z 高度**判定的安全区间（xy 不计入：末端转向/移动会使基座系 xy 大幅变化） |
| **姿态固定** | 末端 RPY 锁死（默认朝下），运动退化为纯平移（路径可预测） |
| **失手急停** | 连续 N 帧检测不到手 → 立即 stop_move()（安全红线） |
| **正运动学 FK** | 由关节角算末端位姿（读取当前末端位置用） |

## 7. 安全注意点（必读）

### 7.1 防剐蹭（高度安全区 z + 姿态固定）

**为什么容易剐蹭**（用户反馈的痛点）：
- 机械臂末端挂着"相机 + 灵巧手"，运动时若姿态变化/越界，极易碰到桌面或机械臂本体；
- 相机、灵巧手是精密器件，剐蹭会导致损坏。

**解决方案**：
1. **姿态固定**：末端 RPY 锁死（默认 [π,0,0] 朝下）→ 运动退化为纯平移，路径可预测；
2. **高度安全区（z 轴，基坐标系）**：末端高度 z 必须在区间 [min_z, max_z] 内
   （z 低于下限 → 防撞桌面；z 高于上限 → 防升太高），越界 → 拒绝执行并告警；
   **xy 不计入**——xy 是相对基座的水平面坐标，末端转向/跟随手到不同方位时 xy 数值
   会大幅变化，若按 xy 固定区间判定会在"末端明明安全"时荒谬误报；
3. **高度区间必须按实际工作台设置**（GUI 可调，单位【米】，默认 0.18 ~ 0.68），
   默认值只是参考。

> ⚠️ 若"臂看起来安全却被判越界"，先看高度安全区面板下的**实时诊断行**（末端z vs 区间）：
> 那是机械臂 SDK 上报的真实法兰 z（基坐标系）与区间的同屏对照——据此把区间调大覆盖
> 实际高度，而不是怀疑误报后直接关掉保护。相机/灵巧手挂在法兰上会向外伸，保护的是
> 高度下限不撞桌面；末端碰撞盒（末端坐标系）另管横向剐蹭（见 7.6）。

### 7.2 失手急停（安全红线）

**用户硬性要求**："机械臂运动过程中，如果失去了相机采集的手部信息，依旧在运动，这是非常危险的"。

**实现**：`arm_follow_eye.py` 中：
- 每帧检查手腕是否检测到（`wrist_3d_cam is None`）；
- **连续 `lost_frames`（默认 5）帧检测不到 → 立即 `stop_move()` 强制停止**；
- GUI 状态显示"⚠️ 连续 N 帧未检测到手 → 已急停"。

> ⚠️ 这是**最后防线**，不要依赖它代替人工注意；操作时仍应随时准备按急停。

### 7.3 速度与限幅

- 首次速度比例 **0.2**（面板滑条可调），确认轨迹稳定再逐步提高；
- 单帧限幅默认 **5mm**（防深度噪声猛冲），可调小到 3mm 更稳；
- 参考 grasp 项目：`set_joint_maxvelc` + `set_end_max_line_velc` 限制速度。

### 7.4 操作规范

1. 开始跟随前：机械臂已连接上电、Holistic 已启动、高度安全区 z 已设置、周围无人；
2. 跟随中保持手在相机视野内，缓慢移动（快移可能触发限幅/丢手急停）；
3. 手腕下移幅度 = 末端下移幅度（1:1 相对），但受高度安全区 z 下限约束（不会碰桌面）；
4. 灵巧手动作模仿与机械臂跟随**独立开关**（可只跟臂、只跟手或都跟）；
5. 异常（机械臂乱动/失控）→ 立即按 GUI"停止跟随(急停)"或物理急停。

### 7.5 完整安全机制（EyeInHandFollower 加固版）

`arm/arm_follow_eye.py` 内置**多层安全链**，任何一层触发都立即【硬停止】（`hard_stop` 多次调用 stopMove 直到确认静止）：

| # | 安全机制 | 触发条件 | 动作 |
|---|---|---|---|
| 1 | **失手急停** | 连续 N 帧（默认5）检测不到手 | hard_stop 硬停止 |
| 2 | **末端姿态硬锁** | 实际末端 RPY 与固定值偏差 > 2°（姿态变了=异常/碰撞） | hard_stop 硬停止 |
| 3 | **碰撞/受阻检测** | 关节力矩 > 8 N·m（碰撞时力矩异常增大） | hard_stop 硬停止 |
| 4 | **运动停滞检测** | 目标在动但实际位置连续 8 帧几乎不动（受阻/卡住） | hard_stop 硬停止 |
| 5 | **高度安全区(z)强制生效** | 目标点/路径 z 越界（基坐标系，xy 不计入），连续 3 帧（不裁剪不继续，直接停） | hard_stop 硬停止 |
| 6 | **锁腕保护** | 缩步到最小仍需转腕 > 硬限 15°（奇异/翻转方向），连续 8 帧 | hard_stop 硬停止 |
| 6b | **锁腕软降级** | 腕差 3°~15°（保持姿态所需） | 缩步取最小腕差解继续，不阻塞 |
| 7 | **相机系静止判定** | 手在相机系位移 < 8mm → 绝不下发（防"手没动臂却动"正反馈漂移） | 拒绝本帧 |

**为什么之前"安全框(高度区)/急停"失效**（重要教训）：
- 旧 GUI 的 `_eye_step` 调用了不存在的 `safety_box.clamp_pos()/is_within()` 方法（异常被吞）→ 形同虚设；
- 旧版安全框把 xy 也计入 → 末端转向/移动到侧面时基座系 xy 大幅变化 → 荒谬误报（已重构为 z-only）；
- 丢手只调一次 `stop_move()`（SDK 忙时可能失败）→ 机械臂继续运动；
- 无碰撞/停滞/姿态检测 → 碰到障碍物不停。

**本次修复**：
- GUI 跟随核心改用 `EyeInHandFollower`（以上多层安全链）；
- 硬停止用 `arm.hard_stop()`（重试直到 `is_steady()` 确认停止）；
- 运动下发前检查 `is_steady()`（机械臂运动中跳过本帧，防指令叠加导致姿态摆动）；
- 姿态固定值从**法兰位姿**读取（`get_flange_pose`，与检测一致，避免 TCP 偏移误差）；
- **默认锁腕运动**（第 6 层）：运动不再用 moveLine，改为 IK 参考角锁腕 + FK 校验 + movej，
  末端三关节 [J4,J5,J6] 全程偏差 ≤ 软容差 3°（超过但在 15° 内则软降级小步走，GUI 可调），
  从根源杜绝 SDK 偷偷转腕带偏设备方向。

### 7.6 末端安全碰撞盒（SDK 硬件级保护）+ 姿态/腕部锁定（第 8 层 + 双保险）

**末端碰撞盒**（依据 `lib/auboDocument/index-碰撞.pdf` 与 SDK 头文件）：
- `addCollisionBox(name, "end_effector", sizes, poses)`：在**末端挂一个随动长方体**
  （尺寸 = 相机 + 灵巧手 + 手指摆动空间），机械臂其它连杆/环境物体进入该盒
  → **SDK 碰撞保护（停止）**——这是最底层的硬件级防剐蹭；
- GUI【机械臂控制】页 → "末端安全碰撞盒"面板：长×宽×高(cm) + 相对末端 z(cm) 可调
  （默认 20×16×25cm，z+10cm，按实际挂载调整）+【启用/停用】；
- 眼在手上【开始跟随】时**自动启用**碰撞盒（除软件安全链外的 SDK 级兜底）；
- ⚠️ 本固件可能不支持（返回 32601 method not found）→ GUI 自动降级提示，由软件多层安全链兜底。

**姿态锁定 + 末端三关节锁定**（用户核心需求：设备始终保持一个方向）：
- 【锁定当前姿态】：读取当前【法兰】姿态 [rx,ry,rz] → 存入 `_locked_rpy` 并启用锁定；
- 锁定后所有 movel 入口自动**强制替换姿态为锁定值**（只移动 xyz，末端朝向不变）；
- 【解除锁定】恢复用输入框姿态；
- 眼在手上跟随自动采用锁定姿态（若已锁定）；
- **开始跟随（wrist_lock 模式）时**：读取当前关节角，把末端三个关节 J4/J5/J6 锁为
  固定值（跟随中几乎不动，偏差 ≤ 软容差默认 3°；>3°~15° 软降级小步，姿态仍锁）。目标点一律以锁腕 IK/FK
  校验后 movej 执行，EyeInHandFollower 每帧双保险：
  ① 实际法兰姿态偏离 fixed_rpy > 2° → 急停；
  ② 目标需大幅转腕才可达（缩步后仍不可行）连续 8 帧 → 急停。

## 9. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 机械臂跟随方向反 | 手眼标定矩阵与安装不符 | 切换备用标定 / 现场重标定 |
| 机械臂不动但手在动 | 增量太小被限幅/手腕静止 | 看状态"Δ"值；加大移动幅度 |
| 频繁急停 | 手离开视野/抖动 | 保持手在视野内；调大丢手帧数（不推荐） |
| 末端位置偏 | 标定偏移（高度区只裁 z，不裁剪 xy） | 微调标定 t 向量 |
| 相机/灵巧手碰桌面 | 高度区 z 下限过高/桌面被下移 | 设低 min_z（z 下限=桌面高度以下留余量） |
| 灵巧手不模仿 | 未勾选"灵巧手跟随" | 协同面板勾选 |
| 机械臂丢失目标仍动 | 旧逻辑未急停 | 确认用 EyeInHandFollower（含失手急停） |
